A shop is the demo. The delivery system is the project.

Inkling is a small demo shop. The real work is the GitOps platform underneath it, which tests, packages, deploys and watches the shop automatically. Here is what each part of this page represents:

On the shelfThe inventory service, a Python microservice that keeps the stock.
Behind the counterThe api service, running as several pods in Kubernetes. Each row is one real request.
Environment tagThe Kubernetes namespace the page runs in: staging for testing, prod for real users.
Running commitThe exact Git commit the running container image was built from.
Answered by podThe specific pod (container) that handled the request.
Red rowsFailed requests, for example during a simulated bad release. They disappear after a rollback.

Shipping software by hand is slow and risky.

Copying files to servers, forgetting a step, and not knowing who changed what are how outages happen. This project makes Git the single source of truth: the cluster always matches what is written in Git.

Safe by defaultTests and a security scan run on every change. Broken or vulnerable code never ships.
Every change recordedWho changed what, when and why lives in Git history, ready for any audit.
Undo in secondsRolling back is a git revert. ArgoCD restores the previous version.
Self-healingManual changes to the cluster are undone automatically within seconds.
A human gate for prodStaging updates itself. Production only changes through a reviewed pull request.
Rebuilt in minutesThe whole platform can be recreated from Git with one command in about 6 minutes.

From a commit to your screen, step by step.

  1. Push. A developer pushes code and opens a pull request in the app repository.
  2. Check. GitHub Actions lints the code, runs the tests, builds a Docker image and scans it with Trivy. Critical vulnerabilities stop the pipeline.
  3. Package. On merge, the image is pushed to GitHub Container Registry, tagged with the commit ID.
  4. Record. A bot writes the new tag into the config repository, the "order book" for staging.
  5. Sync. ArgoCD, running inside the Kubernetes cluster, notices within a minute and rolls out the new version with zero downtime.
  6. Promote. One click opens a pull request that copies the staging version to prod. Merging it deploys production.
  7. Watch. Prometheus collects metrics every 15 seconds, Grafana draws them, and five alert rules notify Discord with a runbook link.
  8. Recover. If a release misbehaves, git revert brings the previous version back automatically.
